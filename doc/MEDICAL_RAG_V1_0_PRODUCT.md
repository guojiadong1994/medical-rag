# Medical RAG V1.0 成品冲刺版

## 1. 这一版解决什么

这一版把前面已经验证过的检索与生成模块从“多个实验脚本”收口成一个真正可调用的完整问答服务。

统一流程：

```text
用户问题
→ BGE-M3 向量检索
→ BM25 关键词检索
→ RRF 排名融合
→ 重排序模型
→ 证据上下文构建
→ 大模型生成
→ 引用检查
→ 返回答案、来源、页码、运行诊断
```

其中：

- BGE-M3：把问题和知识文本转换成向量的嵌入模型。
- BM25：根据关键词和词频进行匹配的传统检索算法。
- RRF（Reciprocal Rank Fusion，倒数排名融合）：按多个检索结果中的排名进行融合，避免直接相加不同量纲的分数。
- Milvus：专门保存和检索向量的数据库。
- 重排序模型：对第一阶段召回的候选证据进行更精细的相关性重新排序。
- 引用检查：检查答案中的 `[S1]`、`[S2]` 是否真实存在于本次证据上下文。

## 2. 新增：统一 MedicalRAGPipeline

过去需要分别运行检索、重排序、上下文构建和生成脚本。

现在核心入口是：

```python
pipeline.ask("2级高血压的收缩压和舒张压范围是多少？")
```

返回内容包括：

- 最终答案；
- 是否因为证据不足而拒答；
- `[S1]` 等来源编号；
- 来源文件、页码、章节；
- 哪些证据真正被答案引用；
- 输入和输出 Token 数；
- 检索、上下文构建、大模型生成分别耗时多少。

Token 指模型处理文本时使用的基本计量单位，不等同于汉字数。

## 3. Milvus 正式进入产品主链

默认：

```text
RAG_DENSE_BACKEND=milvus
```

即向量检索由 Milvus 执行，BM25 仍然使用本地内存索引，再通过 RRF 融合。

仍保留：

```text
RAG_DENSE_BACKEND=local
```

用于回退到本地 NumPy 精确向量检索。NumPy 是 Python 常用的数值计算库。

Milvus 与 macOS 的 MPS 运行顺序仍保留之前验证过的处理：先初始化嵌入模型，再连接并加载 Milvus Collection（向量数据集合），最后才执行 MPS 上的查询向量计算，避免之前遇到的底层崩溃问题。

## 4. Safety Guardrail V1：安全防护规则

这一版针对 V3.1 唯一真实失败增加了“证据边界”规则。

旧问题：

```text
当前证据只支持“不应自行停药”
↓
模型却额外补充
“自行停药可能导致血压反弹、增加心脑血管风险”
↓
这些额外医学后果没有被当前 Top5 证据直接支持
```

新规则要求：

```text
药物后果、停药后果、风险增加、疾病机制、因果关系
↓
必须有当前检索证据直接支持
↓
否则不允许为了“提醒更充分”而调用模型自己的医学常识补充
```

这叫“Evidence-bounded Generation（证据边界生成）”，意思是回答只能扩展到证据真正能够支撑的范围。

## 5. 拒答的引用规则也修正

普通医学事实回答：

```text
必须引用 [Sx]
```

明确的证据不足拒答：

```text
现有检索证据不足以回答该问题。
```

如果没有输出任何医学事实，则不再强制要求 `[Sx]`。

这样避免出现“系统正确拒答，却因为没有引用一个无关证据而被标记为引用失败”的问题。

## 6. FastAPI 接口

FastAPI 是 Python 的网页接口开发框架。

主要接口：

```text
POST /api/v1/rag/ask
```

请求：

```json
{
  "question": "2级高血压的收缩压和舒张压范围是多少？"
}
```

请求头需要：

```text
Authorization: Bearer <登录返回的 accessToken>
```

返回中包括：

```text
answer       最终回答
abstained    是否拒答
sources      证据来源
Diagnostics  运行诊断信息
```

Diagnostics（运行诊断信息）包括模型名称、检索参数、Token 使用和各阶段耗时。

同时提供：

```text
POST /api/v1/me/assistant/chat
```

它与主问答接口共用同一套后端逻辑，便于后续接现有 Vue 前端。

Vue 是用于开发网页界面的前端框架。

## 8. 启动

安装完整成品依赖：

```bash
pip install -e ".[product,dev]"
```

复制配置模板：

```bash
cp .env.example .env
```

把 `.env` 中的大模型地址、模型名称和密钥改成你实际使用的值。

先检查运行条件：

```bash
python scripts/preflight_v1.py
```

再启动：

```bash
python run.py
```

API 文档页面：

```text
http://127.0.0.1:8000/docs
```

演示页面：

```text
http://127.0.0.1:8000/rag-demo
```

## 9. Docker

Docker 是把程序及其运行环境封装成容器的工具。

为了不覆盖仓库原有 `docker-compose.yml`，这一版单独提供：

```text
Dockerfile.rag-v1
docker-compose.rag-v1.yml
```

启动：

```bash
docker compose -f docker-compose.rag-v1.yml up --build
```

注意：Mac 上 Docker 容器不能直接使用宿主机的 MPS 图形处理加速，因此容器版本的本地嵌入模型和重排序模型通常会使用 CPU，速度可能慢于直接在 macOS 的 Conda 环境中运行。

## 10. 当前 V1.0 的边界

这一版是真正可运行的“医疗指南单知识库问答成品”，但以下能力没有伪装成已经完成：

- 患者时间线与指南证据融合：未完成；
- 医学图片与视觉大模型：未完成；
- 知识图谱：未完成；
- 大规模多文档自动入库：未完成；
- 高并发生产部署：未完成。

即使请求带 `patient_id`，当前 V1.0 返回中也会明确：

```text
patient_context_used = false
```

避免让系统假装已经使用了患者资料。

## 11. 验收策略

代码级自动测试：

```bash
pytest -q
```

本成品包制作时结果：

```text
59 passed
```

这 59 个测试不等于医学问答准确率，它只说明当前代码功能的自动化测试全部通过。

真实模型回归仍建议沿用之前的两套题：

```text
14 道正常有答案问题
+ 9 道安全挑战问题
```

Safety Guardrail V1 的重点是验证：原来的 8/9 安全挑战基线能否提升，同时不能破坏原先 14/14 的正常问答能力。
