# Chunking V1.2

本版本目标不是盲目提高“章节覆盖率”，而是降低错误 Section 对 Embedding 的污染，并把 Chunk 质量报告拆得更清楚。

## 主要变化

1. **Section Detector 收紧**
   - `4.5` / `4.5.1` 等带小数点编号仍视为强结构信号。
   - 普通整数标题需要更强的标题形态证据。
   - `95 定义为高血压...`、数值区间、百分位、`mmHg` 等不会再被当作标题。
   - `1 推荐类别`、`2 证据等级` 这类表格残留不再轻易当成章节。
   - 对 `4.5.1 标题 正文...` 这种粘连文本，将标题和正文拆开。

2. **短 Chunk 后处理**
   - `表`、`图`、`注` 等极短抽取噪声直接移除。
   - 低于 `min_chars` 的正文块不会简单删除；只有与相邻正文属于同一章节、合并后不超过 `max_chars` 时才合并。

3. **最大长度统计改进**
   - `max_chars=1200` 只作为 Narrative Chunk 的硬上限。
   - Table Chunk V1 仍优先保持整表，不因 1200 字限制拆表。
   - 报告新增 `narrative_over_max_chunk_count` 与 `table_over_max_chunk_count`，避免把大表误判成正文切块 Bug。

4. **章节审计**
   - 新增 `section_audit.json`。
   - 对含阈值符号、数值范围、句子标点、异常大整数编号等可疑章节做标记，便于人工抽查。
