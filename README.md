# Medical RAG V1.0 · 智护医疗完整项目

这是 **JD 特定人群生理孪生与医疗保障大模型平台**中的多源医疗知识增强检索子系统。当前包恢复了项目原有的 **“智护医疗”完整前端设计**，并把已经完成的真实医疗知识库问答后端接入原有 AI 健康助手页面。

> 当前 V1.0 的真实知识问答范围是《中国高血压防治指南（2024年修订版）》单知识库。个人健康、医疗记录等页面保留原有产品设计和演示数据；患者时间线与真实医院数据接入尚未完成，因此不会把这些演示页面冒充成真实患者数据链路。

## 一、项目现在包含什么

### 1. 原有完整网页产品

`apps/web/` 已恢复并保留原来的产品结构和深青绿色视觉设计：

- 登录页
- 首页
- 我的健康
- 医疗记录
- AI 健康助手
- 设置
- 管理员医疗知识库

AI 健康助手已经不再使用前端写死的假答案，而是调用真实后端知识库问答接口。

### 2. 真实医疗知识库问答主链

```text
PDF 解析
→ 文档清洗
→ 表格解析与数值保真
→ 文本切块
→ BGE-M3 向量表示
→ 向量检索 + BM25 关键词检索
→ RRF 排名融合
→ 重排序模型
→ 证据上下文构建
→ 大模型回答
→ 引用来源
→ 证据绑定与安全评测
```

其中：

- BGE-M3：把文本转换成向量表示的嵌入模型。
- BM25：基于关键词匹配的重要性检索算法。
- RRF：倒数排名融合，把多路检索结果按名次进行合并。
- Milvus：用于保存和检索文本向量的向量数据库。
- Reranker：重排序模型，对初步召回的候选证据再次精细排序。

## 三、保留你本地原有运行数据

你当前机器中已经生成过这些重要文件，它们不会被这个源码包重新生成或覆盖：

```text
data/processed/hypertension_2024/
data/milvus/medical_rag.db
.env
.git/
```

**不要先删除旧项目再解压。** 推荐使用包内的 `SAFE_RESTORE_TO_EXISTING_PROJECT.sh`，它会恢复完整源码和原前端，但不会删除或覆盖 `.env`、`.git` 和已有 `data/` 运行数据。

## 六、目前哪些页面是真实接入

### AI 健康助手

真实调用：

```text
/api/v1/me/assistant/chat
```

回答会返回：

- 最终回答
- `[S1]`、`[S2]` 等引用
- 来源文件
- 页码
- 章节
- 是否被最终答案实际引用

### 医疗知识库管理

真实调用：

```text
GET  /api/v1/knowledge/documents
POST /api/v1/knowledge/documents
```

支持查看当前运行知识库和上传新的 PDF 到待处理目录。

当前“新增 PDF 后自动解析、切块、向量化并重建索引”的一键自动入库还没有接成后台任务，所以界面会明确显示“待处理”，不会伪装成已完成索引。
